# vMAJOR.MINOR.PATCH

## 状态与依据

记录工程日期、真实发布日期（未发布则明示）、源码提交和实际存在的 Tag / Release。不要填写虚构链接。

## 目标与变化

说明相对上一版解决的问题、触发条件和最终行为。按需列新增、修改、修复、移除；无变化的类别省略。

## 开发影响

说明涉及模块、接口与扩展位置、配置/数据兼容、依赖及结构变化；链接现行专题。
首版记录完整能力和模块契约，后续版本记录增量。

## 验证与限制

分别列通过、失败、未执行及证据。性能要记录规模、条件和指标边界；不能混用历次测试。

## 后续优化依据

记录已发现瓶颈、待验证假设、优先级和验收方法，不将计划描述为完成。

## 交付与清理

记录安装/升级注意事项、对应源码和第三方材料、校验清单、删除和保留项及清理清单位置。
